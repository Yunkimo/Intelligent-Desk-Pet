# 大模型辅助开发记录

## 目标与方法

使用 Codex 按评分项阅读代码、检查 Git 历史、提出方案、实现、写文档和验证。不宣称所有生成内容已经团队人工验收。

| 阶段 | AI 辅助内容 | 校验方式 |
|---|---|---|
| 审计 | 比较文档、代码与历史 | git show/diff/log，导出基线重新测试 |
| 实现 | 离线策略、文件边界、参数注入、错误处理 | 正常/异常/故障注入用例、Qt 集成 |
| 工程 | 钩子、CI、度量、提交规范 | Ruff、pytest、pip-audit、远端 CI |
| 文档 | UML、手册、安全、团队模板 | 逐项对应代码/日志，未实测项明示 |
| 协作 | 编写 Issues/PR，按授权推送合并 | 真实账号和 CI，不冒充他人评审 |

## 纠错经验

1. “单文件原型”无法从历史验证，移除而非继续润色。
2. 旧用例假定 F21 不存在，Windows 实测失败，改为验证平台真实能力。
3. 初次审计发现虚拟环境旧 pip 的漏洞记录，升级后重新审计。
4. offscreen 截图最初缺中文字体，用 QT_QPA_FONTDIR 指向系统字体后重新录制。
5. 本地与远端作者不同，使用远端事实并保留本地历史，不重写作者来“补协作”。

团队应复核功能、代码、许可与报告，在展示中说明接受了哪些 AI 建议、为什么接受、如何发现错误。测试通过不等于全部需求或安全风险都已解决。
